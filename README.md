# Mazda Monitor 2.0 — Android + ELM327 Mini (Bluetooth Classic)

Проект новой версии приложения для Mazda CX-5 (2015 г., бензин 2.0) с **выбором датчиков**. Интерфейс на русском. Работает по Bluetooth Classic RFCOMM/SPP с предварительно сопряжённым ELM327 Mini.

> **Статус:** полный исходный проект (Java, Android 8+), **не готовый APK**. В среде создания нет Android SDK / Gradle и нет интернет-доступа к их дистрибутивам: Android APK не собирался и на автомобиле не тестировался. Автономные тесты парсера / вычислений прошли: **43/43**. Дополнительно проведены **9 имитационных тестов обмена ELM327 по потокам данных** (инициализация, OBD2 PID, ошибки, отсутствие данных). Это **не подтверждает обмен с реальным автомобилем**. Важна первичная сборка и проверка на вашем адаптере.

## Что нового в версии 2.0

- Раздел **«Датчики»** с чекбоксами, фильтрами по группам, поиском по названию и PID, кнопками «Базовый набор» / «Очистить». Выбор хранится в SharedPreferences.
- Раздел **«Панель»** автоматически показывает только выбранные показатели в виде крупных карточек (динамически перестраивается).
- Опрос ELM327 только по необходимым **уникальным PID**, плюс зависимости выбранных расчётных данных. Один ответ `0134` даёт и λ, и ток, `0168` — обе температуры впускного воздуха. Неподдерживаемые PID пропускаются, при невозможности получить данные выводится «н/д»/«—».
- Считывание стандартных поддерживаемых PID по маскам `0100`, `0120`, `0140`, `0160` с учётом фактических отказов от адаптера. После `NO DATA` PID выключается до переподключения.
- Подключение к сопряжённому OBDII / ELM327 и чтение стандартных кодов DTC Mode 03 **без их сброса**.
- **CSV** журнал всех определённых полей (сохраняются пустые колонки для неизвестных показателей); экспорт в выбранный файл Android через системный диалог.
- **Настройки** ёмкости бака и цены топлива, учёт поездки, оценки расхода и запаса хода, персональная статистика заправок (контрольная точка 23.10.2026: 306 → 580 км, 24 л).

## Каталог показателей — 56 выбираемых строк

Все показанные на предоставленных скриншотах Car Scanner стандартные PID, для которых известны однозначные формулы, включены как **живой опрос ЭБУ**, а не как заглушки.

| Группа | Реальные PID |
|---|---|
| Двигатель | `0104` расчётная нагрузка, `0143` абсолютная нагрузка, `0105` ОЖ, `010B` MAP, `0133` атмосферное давление, `010C` обороты, `010D` скорость, `010E` зажигание, `010F` IAT, `0168` IAT B1S1/B1S2, `0110` MAF, `0111` дроссель, `0145` относительный дроссель, `0147` дроссель B, `0149` педаль D, `014A` педаль E, `014C` командный дроссель |
| Топливная система и смесь | `0106` STFT B1, `0107` LTFT B1, `0115` B1S2 напряжение/коррекция, `0134` B1S1 широкополосный O2 λ/ток, `0144` командная λ, `0155`/`0156` вторичные кислородные коррекции Bank 1/3 (если есть), `013C` температура катализатора, `012E` EVAP, `0123` и `0159` давление рейки, `012F` уровень топлива, `015E` подача топлива |
| Электрика и история неисправностей | `0142` напряжение ЭБУ, `0121` километры с MIL, `0130` прогревы после очистки кодов, `0131` километры после очистки, `ATRV` напряжение по самому адаптеру |
| Расчётные | вакуум относительно барометра, AFR по λ, расход л/ч и л/100 км, средний расход за последние 10 с, литры в баке (процент × настроенная ёмкость), оценка оставшегося пробега, мощность по MAF и расходу (грубые), путь и расход топлива за текущую сессию, средний расход/скорость, ускорение, стоимость, условная оценка экономичности |

**Важно:** конкретный экземпляр ЭБУ может не поддерживать часть стандартных запросов. Показания на скриншотах Car Scanner не означают, что любое из 56 полей доступен напрямую. Показатели Bank 3 на скриншотах `n/a`; если PID есть, отдельные поля могут быть недоступны. Температуры B1S1/B1S2 декодируются из стандартного 0168 только если указаны в маске сенсоров.

## Прямые измерения vs расчёты

- **PID `015E`:** расход в л/ч измеряется/оценивается ЭБУ, если PID поддерживается; иначе расход **грубо оценивается** по MAF, AFR 14.7 и плотности бензина 745 г/л. При нагрузках, переходных режимах и нестехиометрической смеси оценка может быть неточной.
- **Литры в баке:** `012F` показывает процент; перевод в литры требует вместимости бака. **Начально установлено 50 л** исключительно потому, что Car Scanner показывает 47,45 л при 94,9%, но **это не подтверждение фактической ёмкости Mazda**. Исправьте значение под свою комплектацию.
- **Остаток пробега:** расчёт по баку и среднему расходу текущей поездки; доступен после 2 км статистики, **не штатный расчёт ЭБУ**.
- **Средний расход/скорость, путь, топливо, стоимость:** интеграция за **одну сессию Bluetooth**, сбрасывается при новом подключении. При слабом адаптере точность ограничена частотой обновления.
- **Разрежение:** `(MAP − атмосферное давление) / 100` в барах; отрицательное число означает разрежение.
- **AFR:** `λ × 14.7`, грубая оценка для бензина, если считывается фактическая λ с датчика, иначе берётся командная λ и не является измеренной смесью.
- **Мощность, ECO-балл, ускорение:** приближённые ориентировочные оценки; не данные датчика мощности и не диагностические нормативы.
- **Напряжение:** `ATRV` — адаптер, `0142` — ЭБУ. На скриншотах Car Scanner значения сильно отличаются (16,7 и 14,34 В). Не трактуйте `ATRV` как подтверждённую зарядку аккумулятора; для проверки используйте мультиметр.
- **Расход л/100 км на стоянке:** показывается «—», а не бесконечность.

## Как собрать APK в Android Studio

1. Установите Android Studio с Android SDK API 35, JDK 17 и Gradle **8.11.1**.
2. Распакуйте ZIP, откройте его корневую папку в Android Studio (`File → Open`).
3. Синхронизируйте Gradle; используется Android Gradle Plugin **8.9.2**. Если Android Studio требует Gradle Wrapper, сначала создайте его в локально установленном Gradle: `gradle wrapper --gradle-version 8.11.1`.
4. **Build → Build Bundle(s) / APK(s) → Build APK(s)**. Результат: `app/build/outputs/apk/debug/app-debug.apk`.
5. Установите APK на Android-устройство, разрешив установку из выбранного источника при запросе Android.

**Без Android Studio:** можно загрузить файлы проекта в репозиторий GitHub и вызвать **Actions → Build Android APK → Run workflow**, затем скачать `MazdaMonitor-debug-apk`. Workflow уже включён в `.github/workflows/build-apk.yml` и устанавливает требуемые инструменты сборки. Это требует настройки доступа к GitHub; сборка не проводилась здесь.

## Начало работы

1. Вставьте ELM327 в диагностический разъём на стоянке, включите зажигание.
2. Выполните сопряжение ELM327 в Android Bluetooth: имена часто `OBDII`/`ELM327`; PIN обычно `1234` или `0000`.
3. Разрешите приложению «Устройства поблизости», на вкладке **«Панель»** нажмите **«Выбрать ELM327» → «Подключить»**.
4. Во вкладке **«Датчики»** выберите показатели, затем вернитесь на **«Панель»**. Начните с 6–10 PID: у вашего ELM327 ответы на скриншотах занимают 1–3 с, поэтому при 30–40 PID скорость обновления будет очень низкой. Значения показываются по мере поступления.
5. На вкладке **«Ошибки»** считайте коды при необходимости; на вкладке **«Топливо»** задайте параметры и сохраните CSV.

## Ограничения и безопасность

- Доступ только к стандартному Mode 01 и чтению DTC Mode 03. **Нет команд стирания ошибок, кодирования или управления исполнительными механизмами.**
- Приложение **не выполняет фоновый опрос** после закрытия Activity: только в открытом приложении. При слабом адаптере некоторые данные могут отображаться редко.
- Bluetooth Classic/SPP; для BLE и Wi-Fi адаптеров нужен другой транспорт.
- Приложение не требует геолокации, доступа к интернету или учётной записи. CSV локальный.
- Не используйте телефон за рулём. Не оставляйте дешёвый ELM327 подключённым к заглушённому автомобилю надолго.
- Программу следует считать тестовым прототипом, пока APK не собран и не проверен на реальном автомобиле.

## Файлы

- `SensorCatalog.java` — каталог / группы / выбор / зависимости PID.
- `Elm327Client.java` — Bluetooth Classic, обнаружение PID, очередь опроса, DTC.
- `Elm327Protocol.java` — отправка запросов, приём ответов до символа `>`; отдельно проверен на имитаторе.
- `tools/ProtocolReplayTest.java` — тест имитационного ELM327 с потоками ввода/вывода.
- `ObdParser.java` — расшифровка стандартных Mode 01 / Mode 03, включая мультиполя.
- `Telemetry.java`, `TripCalculator.java` — текущее состояние, расчёты поездки.
- `MainActivity.java` — UI, выбор и сохранение, Bluetooth, история, экспорт.
- `CsvLogger.java` — журнал всех значений.
- `FuelCalibration.java` — заправки и оценка литров до полного.
- `.github/workflows/build-apk.yml` — облачная сборка debug APK.
